# 数据收集与自动化运行需求

本文与[执行协议](../docs/protocol.md)共同定义现行范围。过去的起始时间限制、数量门槛、十二天总周期限制和单个Event便捷答案规则已经退出生产。

## 目标和阶段

从Polymarket重新采集完整、真实、可复现的题源与结算证据，持续按周更新至HF。

```text
公开来源获取 → 整Event筛选 → V1冻结输入与采样名单
            → V3回收原生结算 → 更新完整集与采样集
```

V2构题、题目审查、V4构造题GT及用户答案评测是后续业务处理器。本轮提供统一LLM调用接口，部署指定DeepSeek模型完成真实输出测试后下线；不把接口可用称为四类处理器完成。

## 每周时间

全部时间为UTC。周一17:00开始准备，周二11:00截止特征采集并冻结，周二17:00为计划发题时刻。实际发题后72小时接受答案，随后120小时回收GT，再保留24小时后处理。没有额外的十二天上限。

- 全部冻结Market必须满足`submission_deadline < Market.endDate <= gt_deadline`，一个不满足就排除整个Event，不截取选项。
- 开始／创建日期只作信息，不作为硬筛选条件；`time.end_at`始终为全部冻结Market计划结束时间最大值。
- `endDate`不等于实际结算时间。`resolved_at`缺失保留null，不用更新时间或抓取时刻补造。
- 初次bootstrap使用真实启动时刻，采集预算18小时，完整后可提前冻结，明确`schedule_compliant=false`。
- 截止仍缺数据或证据时保留未完成／失效记录和原因，不延长旧截止，不把部分结果称为完整。

## 来源、规模和采样

先获取显式v1/v2、全部公开状态的来源，记录可见ID边界、分页游标、原始响应和失败；再按完整Event执行日期及原生未决检查。

完整集`full`保存全部合规Event及所有冻结Markets。500—1000及领域分布只作分析，不阻止保存或发布。采样集`balanced`从同一完整输入选择，每个主领域最多200个Event，少于200全部保留，不把剩余名额转给其他领域。

域内按原生系列分层；缺系列时用原始tag ID组合，再缺失时用Event ID。随后按计划结束日分层，使用固定种子20261105与稳定哈希轮询。V1冻结名单，V3不因结果、失效或GT缺失重新采样。

原始`domain`完整保留有序tags.label。派生`primary_domain`使用版本化规则，每Event计一次；未分类单列。空标签、重名或空groupItemTitle、非二元Event结构不做语义筛除；每个原生Market仍保留其两个互补outcome。

## 采集内容

| 内容 | 必须保留的信息 |
| --- | --- |
| Event | 稳定source_id、PM event_id、title、slug、description、原始标签、时间与完整Market成员 |
| Market | market_id、condition_id、版本、题干、独立规则描述、结算来源、计划结束时间、outcome下标和对应token ID |
| 评论 | Event专属主评论、各层回复、缺父回复、公开用户标识、姓名／简介、正文及UTC时间 |
| 成交 | 全部API可见逐笔记录及重数、condition/token、option_label/outcome、方向、单价、份数和UTC时间 |
| 原生GT | 全部冻结Market的生命周期、精确绑定token、最终支付、可得结算时间、观察时间、缺失和冲突 |

评论通过`/comments/keyset`持续游标获取，仅包含Event专属讨论。成交使用`/v2/trades`，每页保持`taker_only=true, filter_type=TOKENS, filter_amount=0.000001`，按官方结束标志确认完成；不聚合、不采样、不按成交内容去重。

GT联合`/v2/resolutions`和`/v2/tokens`核验，绑定condition_id、token_id、module、outcome_index及opposite_token_id。保留0/1和分数支付，不用行情价格代替结算，不根据其他Market的No结果填补未知赢家。原生支付完整性与时间资格分开；后续空响应不能抹掉已核实支付。

## 发布与字段

HF的`basic`、`extended`各有`full`、`balanced`两个split。基础视图保留身份、标题、标签、时间、单份markets结构和native_gt；扩展视图增加Event／Market规则、评论树和逐笔成交。原始Event用source_id，qa_id留给真正构造的题目。

底层使用稳定分区与目标128MiB的JSONL分片，更新只重写相关分区；manifest列出当前分片，statistics保存完整分母、领域、采样成员及GT状态。需要单文件时用download-view固定版本、核验并合并。Parquet作为规范表保存精确十进制字符串；JSONL保留原十进制文本。

## 自动化与维护

- 定时工作在新的公开GitHub运行仓库执行，不依赖当前计算资源。私有开发仓库保留代码历史。
- GitHub每五分钟检查阶段；每次45分钟工作、10分钟检查点宽限、60分钟任务上限，按需跨任务续跑。单生产并发组保证一个写入者。
- 私有HF Bucket保存可恢复工作状态。数据库在runner本地盘关闭后上传，完整校验后才更新完成指针；只恢复完整代次，工作检查点保留最近两代。
- HF Dataset保存已验收的正式数据。免费用量未知或接近预算时停止新增写入并报告，不开启付费资源或擅自删除正式数据。
- 本次明确授权清理本地、HF及GitHub旧API数据、临时副本与旧数据Release；保留代码、需求资料和精简清理记录，不再复制大体积备份。
- 未来正常运行保留完整输入、结果、失败及必要证据，及时回收临时下载和失效工作检查点。

## 模型接口和验证

启智临时部署归属“公共科研项目”，使用全局路径`/inspire/hdd/global_public/public_models/deepseek-ai/DeepSeek-V4.1-Flash-1017`。平台模型登记项可作表单占位，真实模型由运行命令指定；端口使用`${PORT}`。

通过外部GitHub runner验证模型身份、实际普通回答、结构化JSON及思考模式最终内容；HTTP成功或平台RUNNING不足以认定推理可用。失败、空内容或截断均明确报告。API Key仅从安全环境传入，测试结束立即下线该服务。

用户未来提交只需`answer`和`confidence`。置信度评价以答案与参考GT产生的correct=0/1标签计算Brier，不要求另一个gt_confidence。

软件测试、远端运行、完整数据发布、模型接口就绪及真正前瞻评测分别验收。未到期的GT、未实现的LLM处理器和未经测试的效果不能写为完成。
