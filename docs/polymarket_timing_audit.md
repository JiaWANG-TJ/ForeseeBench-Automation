# 历史审计：Polymarket数量与时间窗（2026-11-07）

本报告保留当时冻结的数据、统计与规划讨论。2026-11-08已将数量和领域目标改为描述统计，采用完整保存及每域最多200个Event的采样视图；当前操作规则以[执行协议](protocol.md)为准。

**结论：将后续实现固定为“三天作答＋五天回收”，前后各预留一天，总周期10天。**

同时纠正两个统计口径：

- **“两三万个”是某个时点的开放状态库存，不是一周新增的未决Event数量。**
- **“非体育平均只有约100个合法Event”不成立。** 某个具体时点可以不足100个，但历史窗口的日期候选数量明显高于这个水平。

本报告固定记录2026年11月7日的真实来源核验及已确认规格。历史重建、原生GT核验、工程测试和未来正式批次验收分别报告；运行状态以本文件末尾的实施记录为准。

## 2. “非体育只有100个”是否真实，以及三天与五天的差别

### 历史窗口复算

固定：

- 三天作答；
- 发题前六小时冻结输入；
- 每个Event包含冻结时已经存在的全部Markets；
- 所有这些Market均满足：`提交截止 < endDate ≤ 回收截止`；
- 非体育只计九个已归类领域，未分类另列。

对每种回收长度，测试7个星期位置×24个小时，并分别回看两个已结束周期，共336次窗口测算。

| GT日期窗口 | 最少非体育候选 | 中位数 | 算术均值 | 最多 | 少于100的窗口 |
|---|---:|---:|---:|---:|---:|
| 3天 | 126 | 238.5 | 418.3 | 1,470 | 0/336 |
| 5天 | 148 | 345.0 | 557.8 | 1,662 | 0/336 |

这些窗口大量重叠，且部分覆盖选举高峰，**不能把418.3或557.8解释为独立自然周的稳定平均供给**。但是，它们足以否定“所有三天窗口平均只有约100个非体育日期候选”的说法。

历史成员集合按记录中的 `Market.createdAt` 重建；成员确定之后才检查全部 `endDate`。没有通过挑选结束日期合适的子Market凑数量。由于无法恢复已删除成员、历史日期修订及公开状态，这些仍是历史重建结果，不是当时实际冻结的正式题集。[完整时刻测算](../data/audits/polymarket-timing-20261107/summary/asof-timing-sweep.json)

根因因此更明确：

- 加密、天气的大量题目结束得很快，留足三天作答后，可用数量显著减少。

- 开放状态中还存在计划日期已过的记录，不能直接视为未来合规候选。

### 当前真实API核验

另对11月7日12:30来源参考点下、模拟三天作答后的全部156个非体育五天候选，查询官方 `/v2/resolutions` 和 `/v2/tokens`：

- 查询时间：**11月7日20:01:29—20:02:04 UTC**。
- 覆盖1,873个condition、3,746个资产，169次请求，最终请求失败0。
- **155个Event的全部冻结Markets通过原生未决核验；1个Event排除。**
- 同一来源的三天窗口有**74个**通过原生未决核验。

五天结果逐域为：加密35、金融49、企业10、宏观8、政治12、地缘0、科技10、文化28、天气3。此次原生核验未覆盖体育。

排除的真实例子是[11月6—13日Musk推文数量Event](https://gamma-api.polymarket.com/events/1305851)：各Market的 `endDate` 为11月13日，但11月7日已有两个区间结算、另一个区间进入提议状态，因此整个Event被排除。

这验证了日期预选与原生状态复核必须同时存在；**155个当前未决，不等于未来155个都会按期取得完整GT。**

历史GT补充核验另有独立分母：2,048个非体育Event中，1,371个当前已有全部原生支付结果，658个尚未全部取得，19个存在来源绑定或证据缺行。官方返回的20,995条resolution记录均未提供非空 `resolved_at`，不能据此把已经取得的支付结果算成“没有GT”。

链上有界抽样中，120个已取得支付的condition有114个恢复并验证了实际支付时间；其中38个早于快照中的endDate，76个晚于或等于endDate，最长约68.17小时。该样本只覆盖已支付条件，不能用于宣称总体三天结算率。[抽样结果与边界](../data/audits/polymarket-timing-20261107/summary/chain-gt-pilot-summary.json)

| **整批周期** | 周一17:00—下周四17:00 | **10天** |

准入公式只有一套：

```text
S = publication_at + 72h
R = S + 120h

对冻结Event中的每个Market：
    S < Market.endDate <= R
```

### 采集、领域与冻结

- 初始来源覆盖显式v1/v2及所有公开状态，保留本轮已验证的列表与详情补漏路径；之后再做准入筛选。

- 保留完整候选池，正式题集目标1,000个不同Event，最低有效规模500个；采用固定seed和稳定排序均分名额，供给不足的领域保留实际数量。

### GT与接口调整

- 将默认结束窗口改为5天，提交窗口保持72小时；新批次不再使用30天窗口及自动额外48小时延期。
- 增加统一批次级 `gt_deadline_at=R`、最终处理截止及主领域分类版本；冻结清单显式保存完整Market身份。
- 冻结、发布前及作答期间核查原生状态。任何冻结Market已有提议或结果，保留证据并判定整个Event不合格。
- GT只从真实官方支付证据取得；保存提前、迟到、未决、缺行、绑定失败及冲突，未知值保持未知。
- `resolved_at`缺失时保留真实支付结果；时间资格只能由经过验证的观察区间或独立结算证据证明，不能补造时间。
- 到R停止该批GT回收。后处理阶段使用截止前已取得的证据；不以延长回收或删除失败Event使批次“通过”。
